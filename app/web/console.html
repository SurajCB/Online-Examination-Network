Problem & objectivesProblem Understanding & Architecture · 2 marks

A multi-user online examination where students connect to an exam server over TCP sockets, running inside a Mininet network whose switches are programmed by a Ryu SDN controller. The network monitors and manages exam traffic.

  1. Concurrent TCP exam delivery: login, questions, answers, timer, results.
  2. The controller knows when an exam is running, from application events.
  3. Only assigned seats reach the server; brute-force sources get blocked.
  4. Exam traffic gets a guaranteed-bandwidth queue; traffic is monitored per switch.
  5. Response time and fairness are measured and compared with a baseline.

System architecture

Every exam message leaves a seat inside Mininet and crosses the SDN switches to reach the server. The server reports exam events to the controller, which changes flow rules in response.

How the server works

Socketsocket() → bind() → listen() → accept() loop on TCP port 5000
ConcurrencyOne thread per student, capped by a semaphore (server full → ERROR)
Framing4-byte length + JSON; recv_exact() handles partial reads
TimerServer-side deadline used as the socket timeout → TIME_UP + auto-submit
RobustnessDuplicate login blocked, resume after disconnect, malformed frames rejected

How the two sides talk

The exam server sends small UDP messages to a virtual address 10.0.0.254:6666. A priority-400 rule on every switch hands them to the controller, which answers the ARP for that address itself and checks a shared token and the sender IP.
